## Why

S1 需要把"已有 VPC 的一次终端接入"做成一个可解释、可恢复、可撤回的闭环。现有 v3.4 SDN/VPC 后端已经具备租户/VPC/端口绑定/下发/采集的骨架，但缺少把"一次用户操作"与它的执行尝试、验证证据、撤回边界稳定关联起来的最小语义，导致重复提交可能重复执行、页面刷新无法回到原操作、变更前缓存可能被误当成新接入成功的证据。

## What Changes

- 新增 `sdn_plans`/`sdn_operations`/`sdn_attempts`/`sdn_attempt_units`/`sdn_resource_claims`/`sdn_identity_snapshots` 六张表，把预览计划、执行意图、逐单元尝试、资源声明与历史身份稳定关联起来，满足请求→尝试→逐单元结果→证据的追溯（N1-04/N1-07），并在父对象删除后保留历史（N1-06）。
- 为终端接入新增"预览/执行分离 + 计划失效重校验"语义：执行前重新校验成员准入、受保护接口、绑定冲突、地址与目标 VPC 前置部署，对象被旧入口改变后拒绝照常执行（N1-03/N1-09）。
- 新增"目标 Leaf 未部署该 VPC 时明确阻塞"的前置检查，不再把端口接入静默扩大为整机 VPC 部署（N1-03）。
- 为接入/验证新增幂等与去重：相同 `idempotency_key` 返回同一操作；deployment 仍只允许 `pending` 态 apply；完成验证不重放已完成配置（N1-04）。
- 把"执行成功 / 配置回读 / 业务验证 / 证据新鲜度"四维状态与证据来源显式分离；采集失败与未知用独立状态表达，不伪装成成功或空列表（N1-02/N1-05/N1-10）。
- 为"撤回本次新增"增加仅处理本次新建且无新引用绑定的守卫，保留租户/VPC/网关与其他端口（N1-08）。
- 新增 VPC 接入情况聚合读取端点，一次返回绑定、部署、最新校验与证据元数据，供前端 fixture 与详情下钻使用（N1-01/N1-06）。

本 change 只定义方案、规格、任务与契约样本，不写应用业务实现；实施在后续 apply 工作包执行。

### Modified Capabilities

- `sdn`: 在既有租户/VPC/端口绑定/下发/采集能力之上，新增 S1 终端接入闭环的后端需求（操作关联、幂等、前置部署检查、预览失效重校验、证据新鲜度分离、采集失败显式化、受控撤回、聚合读取）。

## Impact

- 代码：`backend/app/models.py`（新增 `SdnOperation`，三张既有表加可空 `operation_id`）、`backend/app/routers/sdn.py`（预览/执行/聚合读取/受控撤回端点及守卫）、`backend/app/services/*`（预检补全、幂等与证据语义）、`backend/migrations/versions/012_*`（新增表与列，幂等守卫）。
- 兼容：`operation_id` 全部可空，历史 deployment/binding/snapshot 不受影响；旧入口（v3.3/v3.4 扩容、下发、撤回）继续走同一 `sdn.py` 业务服务，不新建平行执行链。
- 契约：新增 `contract-examples.json` 描述拟议契约（正常/未知/过期/部分失败/预览失效/重复请求/受控撤回），非已实现 API。
- 测试：新增幂等、前置部署、预览失效、受控撤回、证据新鲜度、采集失败等 mock 测试，运行于 QA 容器，不连真机。
