# NEXT 产品蓝图与一期范围

## Why

用户希望在基础能力开发之外，以产品视角设计下一代网络工作台，同时保留业务操作与底层分析能力。长期方向需要分阶段兑现，不能把整份蓝图当成一次发版任务。

## What Changes

- 新增 `PRD-VNEXT.md`，说明愿景、业务语义、前端信息结构、后端演进边界和阶段路线。
- 在总蓝图之后定义一期“已有 VPC 的终端接入与验证”范围、可委托工作块和可验收结果。
- 记录协作责任：Codex 主导前端设计与主实现，审核后端拆分和关键配置联动；用户决定范围、阶段验收及开始收尾的时机。
- 增加 `collaboration.md` 作为一期后端交接、双向反馈和审核入口；具体实现进度仍由各实施 change 维护，避免用户反复转述。
- 在 README 和路线图增加 Draft 入口，不更改既有版本完成状态。

## Capabilities

### New Capabilities

- `next-product-planning`: 要求产品蓝图区分长期方向、一期边界、责任与待确认状态；仅约束规划文档。

### Modified Capabilities

- None. 本 change 不修改 SDN、前端工作台或设备执行的运行规格。

## Impact

仅文档改动。与 v3.4 并行开发 / 收尾并存，不覆盖其代码、任务或决策。未来实施须在用户确认一期边界后单独提出 change。

## Non-Goals

- 不实施前端、后端、数据库、容器或设备配置变更。
- 不冻结一期 API / 库表，不规定后端必须拆成固定数量的任务。
- 不把 NEXT 定为 v4.0，不归档未实现的未来能力，不擅自提交、推送或发版。
